# YT Manager

Десктоп-приложение на PyQt6 для автоматизации полного цикла:
«YouTube-канал → скачивание → монтаж (композиция) → нарезка клипов →
подготовка к публикации в TikTok Studio».

## Быстрый старт

### Требования
- Python 3.10+ (рекомендуется 3.11)
- `ffmpeg` в PATH
- `yt-dlp` (ставится из `requirements.txt`)

### Установка
```bash
cd yt_manager
pip install -r requirements.txt
```

### Запуск
- Linux / macOS: `./run.sh`
- Windows: `run.bat` (или двойной клик по `START.bat`)
- Вручную: `python main.py`

При первом запуске создаются папки `data/`, `каналы/`, `обработанное/`,
`клипы/`, а также `config.json` с дефолтными настройками.

## Вкладки

| Вкладка | Назначение |
|---|---|
| YouTube каналы | Добавление YouTube-каналов, привязка TikTok-хэндла, управление видео |
| TikTok каналы | Карточки TikTok-каналов, статистика, хэштеги, график публикаций, скрипты |
| Автоматизация | Пайплайн на канал: фильтры, скачивание, монтаж, нарезка клипов, авто-триггер |
| Обработка | Ручная композиция: нарезка, склейка, стекинг (baннер/удержание/фон) |
| Публикация | Список скриптов для публикации, кнопки «Скопировать / Готово / Отмена» |
| Файлы | Файловый менеджер с длительностью, размером, превью |
| Статистика | Метрики по каналам и видео, графики |
| Пресеты | Экспорт / импорт полной конфигурации (настройки + каналы + автоматизация) |
| Видео-генератор | TTS + typewriter-видео (отдельный инструмент) |
| Настройки | Лимит диска, тема, TikTok bridge, userscript |

## Файловая структура

```
<project>/
├── каналы/<tiktok_handle>/<youtube_channel>/*.mp4   # скачанное
├── обработанное/<tiktok_handle>/*.mp4                # после монтажа
├── клипы/<tiktok_handle>/<имя_видео>/clip_001.mp4    # нарезанные клипы
├── downloads/                                        # старые пути (совместимость)
├── processed/                                        # старые пути (совместимость)
├── data/app.db                                       # SQLite-база
├── assets/themes/{dark,light}.qss                    # темы
└── config.json
```

При сохранении файлов имена автоматически очищаются от кодов в квадратных
скобках (например, `Video [abc123XY].mp4` → `Video.mp4`). При первом
запуске новой версии выполняется одноразовая миграция старых файлов в
папках `downloads/`, `каналы/`, `обработанное/` (флаг
`filenames_migrated_v1` в `app_settings`).

## Автоматизация

На вкладке «Автоматизация» для каждого YouTube-канала можно включить:

1. **Скачивание** — новые видео по фильтрам (длительность, возраст,
   популярные в запас) попадают в очередь загрузок.
2. **Монтаж** — авто-композиция скачанных видео поверх баннера, блока
   удержания и фона. Папки проверяются перед стартом через
   `validate_processing_dirs`: если какой-то путь не существует или в
   нём нет видео, шаг пропускается с понятным сообщением, а пайплайн
   продолжается дальше.
3. **Нарезка клипов** — физическая нарезка обработанных видео на клипы
   заданной длительности в `клипы/<handle>/`. Если «обработанное/»
   пусто (например, папки монтажа невалидны), нарезка автоматически
   переключается на исходные скачанные видео, чтобы дать результат.

Авто-триггер обходит все каналы каждые 15 минут и добирает клипы до
буфера `clip_min_buffer` (по умолчанию 10) для каждого привязанного
TikTok-канала.

## Куки YouTube

YouTube для защиты от ботов может потребовать авторизацию. Ошибка в
логе выглядит так:

```
ERROR: [youtube] XXXX: Sign in to confirm you're not a bot.
Use --cookies-from-browser or --cookies
```

В этом случае приложению нужно передать в `yt-dlp` куки с залогиненного
YouTube-аккаунта. Режим настраивается на вкладке
**Настройки → «YouTube — куки для скачивания»**.

### Режимы

1. **Автоматически** — приложение пробует `cookies.txt` рядом с проектом,
   затем браузеры `chrome / firefox / edge / brave / opera`
   (в таком порядке). Это поведение включено по умолчанию и
   обратно-совместимо со старыми версиями.
2. **Из браузера** — явно указывается, из какого установленного браузера
   читать куки: `chrome`, `firefox`, `edge`, `opera`, `brave`, `vivaldi`,
   `chromium`, `safari`. Важно: под Windows у Chrome 127+ может
   потребоваться расшифровка DPAPI — если режим не работает,
   используйте вариант «Из файла».
3. **Из файла cookies.txt** — вы сами экспортируете куки и указываете
   путь к файлу. Самый надёжный вариант для серверов, OneDrive и
   ситуаций, когда yt-dlp не может прочитать куки браузера.

После выбора нажмите **«Проверить куки»** — кнопка запустит быстрый
тест через `yt-dlp` в отдельном потоке (UI не зависает). Зелёная галочка
подтверждает, что куки принимаются YouTube.

### Как экспортировать cookies.txt

1. Залогиньтесь в YouTube в браузере.
2. Установите расширение-экспортёр, например **Get cookies.txt LOCALLY**
   для [Chrome](https://chromewebstore.google.com/) /
   [Firefox](https://addons.mozilla.org/) (ищите по названию,
   соблюдайте формат Netscape).
3. Откройте любой YouTube-URL и нажмите в расширении
   «Export → Netscape cookies.txt».
4. Сохраните файл (например, рядом с проектом как `cookies.txt`) и
   укажите путь в Настройках → режим «Из файла».

Файл обновляйте раз в несколько недель — куки устаревают.

### Диагностика ошибок

Приложение автоматически распознаёт типичные ответы YouTube и выводит
понятные сообщения в журнале Автоматизации (подсветка `[!]` красным):

- `Требуются куки YouTube…` — нужна настройка куки.
- `YouTube ограничил частоту запросов (429)` — подождите 10–30 минут.
- `Видео с возрастным ограничением — нужны куки авторизованного
  аккаунта.` — экспорт cookies.txt из залогиненной сессии.

## Troubleshooting yt-dlp

### Ошибка «Sign in to confirm you're not a bot»

YouTube периодически усиливает бот-проверку, и yt-dlp нужно обновлять.
Пошагово:

1. **Настройки → «YouTube — куки для скачивания» → «Обновить yt-dlp»** —
   кнопка запускает `pip install -U yt-dlp`. Это решает большинство
   случаев без дополнительных действий.
2. Убедитесь, что включён чекбокс **«Мобильные клиенты YouTube
   (обход проверки бота, ios/android/web)»** — он по умолчанию ВКЛ.
   Внутри yt-dlp используются `extractor_args={"youtube":
   {"player_client": ["ios","android","web"]}}`, что часто проходит
   проверку даже без куки.
3. Если не помогло — подставьте `cookies.txt` (см. раздел выше).
   Выберите режим **«Из файла cookies.txt»** и нажмите **«Проверить
   куки»** — появится окно с деталями (какие куки применились, список
   форматов для двух тестовых видео, полный текст ошибки при сбое).
4. Для выкачки с куков **заведите отдельный «sacrificial» YouTube
   аккаунт**. YouTube может заблокировать аккаунт, чьи куки
   используются массово из автоматизации — не рискуйте основным.

### Ошибка «Requested format is not available»

Это значит, что YouTube не отдаёт выбранное качество (например, 1080p
для этого видео). Приложение **автоматически повторяет скачивание** с
форматом `best` (без `format_sort`) — обычно достаточно. Если падение
повторяется:

- Обновите yt-dlp (см. шаг 1 выше).
- Понизьте качество в настройках канала (1080p → 720p).

### Лог применяемых куки

В лог `data/app.log` при каждом запросе пишется строка:

```
cookies: mode=file, result={'cookiefile': '/path/to/cookies.txt'}
cookies: mode=browser, result={'cookiesfrombrowser': ('chrome',)}
cookies: mode=auto, result={}            # автологика ничего не нашла
```

Это удобно для диагностики: если настройки UI не применяются —
строка покажет реальный режим.

## TikTok-интеграция

Bridge-сервер (`127.0.0.1:8765`) и userscript для TikTok Studio лежат
в `yt_manager/tiktok/`. Запуск bridge управляется из «Настройки».

## Разработка

- UI — PyQt6, никаких PySide.
- БД — `db.py`, ручной SQLite-слой, миграции через `ALTER TABLE` в
  try/except (неразрушающие).
- Тяжёлые операции (скачивание, ffmpeg) — всегда в `QThread`.
- Имена файлов — `utils.clean_video_name` / `strip_bracket_codes` +
  `sanitize_filename`.
